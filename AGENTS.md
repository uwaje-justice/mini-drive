# File Uploader API

A personal storage backend (mini Google Drive). It handles registration, login,
folders, uploads, previews, downloads, search, and expiring share links through
a JSON REST API. The React client will be the only browser UI.

## Stack

- Node.js with Express 5, ES modules
- Prisma 7 with SQLite for development (`@prisma/adapter-better-sqlite3`, `dev.db`)
- Passport.js with session-based auth
- Multer for uploads
- express-validator for input validation
- Local filesystem for development and Cloudinary for remote storage
- Vitest with Supertest for tests

### What goes where

- `src/app.js` creates the API app and exports it for tests.
- `src/server.js` reads `PORT` and starts the HTTP server.
- `src/api/routes/` wires URLs only. `src/api/controllers/` calls services and sends JSON or binary responses.
- `src/api/serializers.js` defines every response shape. Never return Prisma rows directly.
- `src/api/middleware/` holds API auth, validation, 404, and response header checks.
- `src/services/` holds database access and business rules. No Express code here.
- `src/validators/` holds express-validator chains, one file per feature.
- `src/errors/` holds custom errors with status codes, thrown by services and middleware.
- `src/lib/` holds shared helpers: env, Prisma client, storage adapters, file signatures, pagination, previews, download headers, and streaming.
- `src/middleware/` holds app-wide CSRF, upload, 404, and error handling.
- `src/generated/prisma/` holds the generated Prisma Client. Never edit it by hand. Gitignored.
- `prisma/` holds the schema and migrations.
- `uploads/` holds local files when `STORAGE_DRIVER` is `local`. Gitignored.
- `tests/` holds API, storage, library, and server tests. Tests use `test.db`, never `dev.db`.

### Rules for this structure

- There is no EJS or server-rendered HTML. Keep the backend API-only.
- The React client will live in `client/`; define its structure before scaffolding it.
- Routes only wire URLs. Business logic goes in services.
- Services must not import Express.
- The API and storage drivers share services, validators, and errors. Do not duplicate business rules.
- Switch storage with `STORAGE_DRIVER`. Register new providers in `src/lib/storage.js`; controllers stay unchanged.
- Do not add a second HTTP layer. Any future UI uses this API.

## API contract

- Every route is under `/api`.
- Success: `{ data }`. Failure: `{ error: { code, message, fields? } }`.
- Auth uses the session cookie. Every mutation sends the CSRF token in `x-csrf-token`.
- `GET /api/auth/session` returns the signed-in user or `null`, plus a CSRF token.
- Never expose storage keys, storage URLs, name keys, password hashes, or owner IDs.
- JSON and binary errors use `no-store` and `nosniff`.
- Public shares add `no-referrer` and `noindex, nofollow`.
- Uploads accept up to 10 files. A clean batch returns `201`; any skipped files return `207`.
- Authentication failures return JSON `401`, never a redirect.
- Unknown routes return JSON `404`.

## Commands

- `npm run dev` starts the server with nodemon.
- `npm start` starts the server.
- `npm test` runs the Vitest suite against `test.db`.
- `npm run test:watch` runs Vitest in watch mode against `test.db`.
- `npm run prisma:migrate` creates a migration and regenerates the client.
- `npm run prisma:generate` regenerates the Prisma client.
- `npm run prisma:studio` opens Prisma Studio.

## Notes

- Keep `agent-notes.md` updated and never commit it.
- `.env` is gitignored. Keep required variables listed in `.env.example`.
- `STORAGE_DRIVER` is `local` by default. Set it to `cloudinary` and fill the
  Cloudinary variables to use remote storage.
- Each `File` row records its own `storageProvider`, so local and Cloudinary
  files can coexist.
- Cloudinary previews and downloads are proxied through Express; the browser
  never receives a direct Cloudinary URL.
- The API is same-origin with the future client. CORS is not enabled; use a Vite
  dev proxy during client development.
- Folder and file listings show 20 items per page. The API uses `page` for files
  and `folderPage` for folders.
- Public share links use random UUID tokens, expire after 1-365 days, and can be
  revoked. Expired, revoked, and unknown links all return the same 404.
- Share links may point at nested folders and include descendants, but never
  root files.
- Previews are inline and limited to images, PDF, and plain text.
- Test files prefixed `api-` cover HTTP behavior. `lib`, `storage`, and `server`
  tests cover backend internals used by the API.
