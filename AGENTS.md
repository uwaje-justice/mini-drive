# File Uploader

A stripped-down personal storage app (mini Google Drive). Users register, log in,
create folders, upload files, view file details, download files, and share folders
through expiring links.

## Stack

- Node.js with Express 5, ES modules
- EJS server-rendered views
- Prisma 7 with SQLite for development (`@prisma/adapter-better-sqlite3`, `dev.db`)
- Passport.js with session-based auth
- Multer for uploads
- express-validator for input validation
- Local filesystem for development and Cloudinary for remote storage
- Vitest with Supertest for tests

### What goes where

- `src/generated/prisma/` holds the generated Prisma Client. Never edit it by hand. Gitignored.
- `prisma/` holds the schema and migrations. Prisma's expected location.
- `public/` holds CSS, browser JS, and other static assets. Served by Express.
- `src/app.js` creates the app and exports it for tests.
- `src/server.js` reads `PORT` and starts the HTTP server.
- `src/api/` holds the JSON API for the React SPA. Its controllers call the same services, then send JSON or binary data. No EJS here.
- `src/api/serializers.js` defines safe API response shapes. Never return Prisma rows directly.
- `src/api/middleware/` holds JSON-only auth, validation, 404, and header checks.
- `src/config/` holds one-time setup for Passport and sessions.
- `src/errors/` holds custom error classes with status codes, thrown by services and middleware.
- `src/lib/` holds shared singletons and helpers: env reader, Prisma client, storage adapters, file signatures, pagination, preview rules, download headers, and size formatting.
- `src/middleware/` holds request-level checks: CSRF, auth guard, multer upload, validation, 404, and the error handler.
- `src/routes/` wires URLs to controllers only.
- `src/controllers/` reads the request, calls a service, then renders or redirects.
- `src/services/` holds database access and business rules. No Express code here.
- `src/validators/` holds express-validator chains, one file per feature.
- `src/views/` holds EJS pages grouped by feature, plus shared partials.
- `uploads/` holds local files when `STORAGE_DRIVER` is `local`. Gitignored.
- `tests/` holds service, storage, and HTTP tests. Tests use `test.db`, never `dev.db`.

### Rules for this structure

- Do not move static files into `src/`. They live in root `public/`.
- Routes only wire URLs. Business logic goes in services.
- Services must not import Express.
- Switch storage with `STORAGE_DRIVER`. Add a provider as a driver and register it in `src/lib/storage.js`; controllers stay unchanged.
- Keep the legacy EJS routes, controllers, views, and tests working until the React SPA reaches parity.
- API routes use the `/api` prefix and return `{ data }` on success or `{ error: { code, message, fields? } }` on failure.
- API authentication uses the same session cookie. Mutations send the CSRF token in `x-csrf-token`.
- API responses go through serializers. Do not expose storage keys, storage URLs, name keys, password hashes, or owner IDs.
- The API and legacy EJS app share services, validators, errors, and storage. Do not duplicate business rules.

## Commands

- `npm run dev` starts the server with nodemon.
- `npm start` starts the server.
- `npm test` runs the Vitest suite against `test.db`.
- `npm run test:watch` runs Vitest in watch mode against `test.db`.
- `npm run prisma:migrate` creates a migration and regenerates the client.
- `npm run prisma:generate` regenerates the Prisma client.
- `npm run prisma:studio` opens Prisma Studio.

## Notes

- Keep `agent-notes.md` updated and never commit it.
- `.env` is gitignored. Keep required variables listed in `.env.example`.
- `STORAGE_DRIVER` is `local` by default. Set it to `cloudinary` and fill the
  Cloudinary variables to use remote storage.
- Each `File` row records its own `storageProvider`, so local and Cloudinary
  files can coexist.
- Cloudinary previews and downloads are proxied through Express; the browser
  never receives a direct Cloudinary URL.
- Pages and API mutations use session-backed CSRF tokens. The API reads the
  token from `x-csrf-token`; multipart EJS uploads apply CSRF after Multer so
  the hidden `_csrf` field is parsed.
- `GET /api/auth/session` returns the signed-in user or `null`, plus a CSRF
  token. Login, logout, and registration use the same session cookie.
- Folder and file listings show 20 items per page. EJS folder pages use
  `folderPage`; EJS file pages use `page`. The API uses `page` everywhere.
- Uploads accept up to 10 files. Bad type, empty, long-name, or duplicate files
  are skipped with a per-file message; an oversized file rejects the batch. The
  API returns `201` when every file is accepted and `207` when any are skipped.
- API binary routes stream through Express. Public share routes add no-store,
  no-referrer, noindex, and nosniff headers.
- `GET /api/health` checks that the app is running. All other API routes live
  under the groups in `src/api/routes/index.js`.
- Fonts come from `@fontsource-variable/roboto` and are served at `/fonts/roboto`.
  Use `--font-family-base` from `public/css/tokens.css`.
- Landing-only styles live in `public/css/landing.css`. Shared tokens and base
  styles apply to every page.
- Auth pages use a full-viewport split layout with no site header. The decorative
  panel lives in `auth-visual.ejs`; the accessible "Back to home" link sits in
  the form panel. `public/js/auth-validation.js` mirrors server auth rules, but
  the server stays authoritative.
- Signed-in pages use the sidebar shell in `app-sidebar.ejs`. The sticky search
  bar in `app-topbar.ejs` renders only on `/search`. `currentPath` drives active
  navigation. Public share pages keep the site header and never use the app shell.
- Successful registration and login redirect to `/folders`. Signed-in visitors
  to `/auth/login` or `/auth/register` also redirect to `/folders`.
- Shared list components and Drive page styles live in `drive.css`. Shell,
  form, and file-detail styles live in `app.css`. Generic form controls live
  in `base.css` for both auth and app pages.
- The drive UI uses inline SVG icons from `file-icon.ejs`; no icon library or
  app JavaScript is required.
