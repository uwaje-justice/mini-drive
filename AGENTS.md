# Mini Drive

Mini Drive is a personal storage app. The Express API handles
registration, login, folders, uploads, previews, downloads, search, and
expiring share links. The React client is the only browser UI.

## Stack

- Node.js with Express 5, ES modules
- Prisma 7 with SQLite for development (`@prisma/adapter-better-sqlite3`, `dev.db`)
- Passport.js with session-based auth
- Multer for uploads
- express-validator for input validation
- Local filesystem for development and Cloudinary for remote storage
- React 19, React Router 7 object routes, TanStack Query, React Hook Form,
  Tailwind CSS 4, Motion, React Icons, and Vite 8
- Vitest with Supertest for API tests
- ESLint 10 with `eslint-plugin-simple-import-sort`

### What goes where

API:

- `api/src/app.js` creates the API app and exports it for tests.
- `api/src/server.js` reads `PORT` and starts the HTTP server.
- `api/src/routes/` wires URLs only. Route files end in `-routes.js`; `index-routes.js` combines them. `api/src/controllers/` calls services and sends JSON or binary responses.
- `api/src/serializers.js` defines every response shape. Never return Prisma rows directly.
- `api/src/responses.js` holds the JSON success helper.
- `api/src/middleware/` holds app-wide CSRF, upload, 404, and error handling, plus API auth, validation, and headers. All failures go through the error handler; middleware never writes error JSON.
- `api/src/services/` holds database access and business rules. No Express code here.
- `api/src/validators/` holds express-validator chains, one file per feature.
- `api/src/errors/` holds custom errors with status codes, thrown by services and middleware.
- `api/src/lib/` holds shared helpers: env, Prisma client, storage adapters, file signatures, pagination, previews, download headers, and streaming.
- `api/src/generated/prisma/` holds the generated Prisma Client. Never edit it by hand. Gitignored.
- `api/prisma/` holds the schema and migrations.
- `api/uploads/` holds local files when `STORAGE_DRIVER` is `local`. Gitignored.
- `api/tests/` holds API, storage, library, and server tests. Tests use `test.db`, never `dev.db`.

Client:

- `client/src/main.jsx` mounts React, fonts, global CSS, providers, and the router.
- `client/src/app/router.jsx` owns the object route table and lazy page imports. `providers.jsx` wraps TanStack Query and Motion.
- `client/src/pages/` holds one thin component per screen. Pages compose feature components; they do not call `fetch`.
- `client/src/features/` holds domain components and hooks. The `drive` feature owns dashboard, category, folder, and file-detail data. Add `search` and `shares` as each feature is built.
- `client/src/components/` holds shared layout, routing guards, and UI primitives. The landing and About pages share `layout/landing-header.jsx` and `layout/landing-footer.jsx`.
- `client/src/api/api-client.js` is the only place that calls `fetch` and handles CSRF retries. Resource modules such as `api/auth.js`, `api/drive.js`, and `api/files.js` wrap it.
- `client/src/lib/query-keys.js` owns every TanStack Query key. `query-client.js` configures the client.
- `client/src/styles/globals.css` is the only stylesheet. It imports Tailwind, defines MD3 tokens in `@theme static`, and holds the base and landing styles.
- Use MD3 token names directly: `primary`, `on-primary`, `primary-container`, `surface`, `on-surface`, `on-surface-variant`, `outline-variant`, `error`, `success`, and `warning`. Do not add alias token names.
- Use the `@/` alias for `client/src` instead of deep relative paths.
- New screens use Tailwind utilities and shared UI components. Do not add page-level CSS files.
- Import Motion from `motion/react`, respect reduced motion, and use it only for meaningful transitions.
- Import React Icons directly from a pack such as `react-icons/fi`; do not create icon barrel files.

### Rules for this structure

- There is no EJS or server-rendered HTML. Keep the backend API-only.
- Routes only wire URLs. Business logic goes in services.
- Services must not import Express.
- The API and storage drivers share services, validators, and errors. Do not duplicate business rules.
- Switch storage with `STORAGE_DRIVER`. Register new providers in `api/src/lib/storage.js`; controllers stay unchanged.
- Do not add a second HTTP layer. The client uses this API.
- Never expose storage keys, storage URLs, name keys, password hashes, or owner IDs.
- Client data comes from TanStack Query hooks, never page-level `fetch`.
- Auth state comes from the session query and cookie. Never store it in `localStorage`.
- Run all npm commands from the repository root. Use `-w` for one workspace.

## API contract

- Every route is under `/api`.
- Success: `{ data }`. Failure: `{ error: { code, message, fields? } }`.
- Auth uses the session cookie. Every mutation sends the CSRF token in `x-csrf-token`.
- `GET /api/auth/session` returns the signed-in user or `null`, plus a CSRF token.
- `GET /api/drive/overview` returns all-drive file and folder counts, smart category counts, and the eight newest file or folder creation events.
- `GET /api/drive?page=&folderPage=` returns top-level files and folders with separate pagination.
- `GET /api/drive/categories/:category?page=` returns one type category across the whole drive. Categories are `photos`, `documents`, `text`, and `other`.
- `PATCH /api/auth/email` requires `email` and `currentPassword`. A duplicate email returns `409` with the `email` field.
- `PATCH /api/auth/password` requires `currentPassword`, `newPassword`, and `confirmPassword`. It keeps the current session and deletes the user's other sessions.
- Account changes return the updated session `{ user, csrfToken }`. A wrong current password returns `401` with the `currentPassword` field.
- Validated request fields are available as `req.validated`. Registration also requires `confirmPassword`.
- JSON and binary errors use `no-store` and `nosniff`.
- Public shares add `no-referrer` and `noindex, nofollow`.
- Uploads accept up to 10 files. A clean batch returns `201`; any skipped files return `207`. A request with no files returns `400`.
- Authentication failures return JSON `401`, never a redirect.
- Unknown routes return JSON `404`.
- Public share breadcrumbs start at the shared folder. Ancestors and the shared root's real `parentId` stay hidden.
- File responses include `folder: { id, name }`, or `null` at the drive root.

## Commands

- `npm run dev` starts the API and Vite together.
- `npm run dev:api` starts the API with nodemon.
- `npm run dev:client` starts the Vite dev server.
- `npm start` starts the API server.
- `npm run build` builds the client into `client/dist`.
- `npm test` runs the Vitest suite against `api/test.db`.
- `npm run test:watch` runs Vitest in watch mode.
- `npm run lint` checks the API and client.
- `npm run lint:fix` fixes lint issues and sorts imports.
- `npm run prisma:migrate` creates a migration and regenerates the client.
- `npm run prisma:generate` regenerates the Prisma client.
- `npm run prisma:studio` opens Prisma Studio.

## Notes

- Keep `agent-notes.md` updated and never commit it.
- `api/.env` is gitignored. Keep required variables listed in `api/.env.example`.
- `STORAGE_DRIVER` is `local` by default. Set it to `cloudinary` and fill the
  Cloudinary variables to use remote storage.
- Each `File` row records its own `storageProvider`, so local and Cloudinary
  files can coexist.
- Cloudinary previews and downloads are proxied through Express; the browser
  never receives a direct Cloudinary URL.
- The API and client share an origin in development through the Vite proxy
  (`/api` to `http://localhost:3000`). CORS is not enabled.
- Express does not serve `client/dist` yet. Production client serving is a later step.
- Folder and file listings show 20 items per page. The API uses `page` for files
  and `folderPage` for folders.
- Smart categories are read-only, whole-drive views. Photos match `image/*`,
  Documents match PDF, Text matches `text/*`, and Other is the rest.
- The overview hides Other while its count is zero. Category pages still accept
  an empty `other` list.
- Recent activity is derived from file and folder `createdAt` values. It shows
  creations only; renames, moves, and deletions have no activity history.
- The dashboard routes are `/drive`, `/drive/files`, `/drive/folders`,
  `/drive/categories/:categoryId`, `/drive/files/:fileId`,
  `/drive/folders/:folderId`, and `/drive/settings`.
- Files and Folders pages list top-level items only. Nested items appear inside
  folder pages, recent activity, and smart categories.
- Public share links use random UUID tokens, expire after 1-365 days, and can be
  revoked. Expired, revoked, and unknown links all return the same 404.
- Share links may point at nested folders and include descendants, but never
  root files.
- Previews are inline and limited to images, PDF, and plain text.
- ESLint 10 tracks JSX references natively, so no React lint plugin is needed.
- `api/tests/` uses feature names for HTTP behavior: `auth.test.js`,
  `drive.test.js`, `files.test.js`, `folders.test.js`, `search-share.test.js`,
  and `security.test.js`. `lib`, `storage`, and `server` tests cover backend
  internals used by the API.
